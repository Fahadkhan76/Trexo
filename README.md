# Trexo (Hackathon Demo)

See [ROADMAP.md](ROADMAP.md) for planned development stages. Coding agents should also read [day1Report.md](day1Report.md) before planning upgrades.

**Free your cash. Never run out.**

A desktop billing, dead-stock cash rescue, and restock planning demo built for rural Indian kirana owners.

> **Connectivity & Persistence:** Works with unreliable connectivity; all data is saved on this device in `localStorage`. *(This demo has no service worker and does not load offline from a cold browser refresh.)*

## Core Demo Story

1. Inspect **Cash trapped in dead stock** and **Estimated sales lost to stockouts** on the Counter or Inventory hero strip.
2. Open **Rescue Stuck Cash**, apply a counter discount to a slow/dead item (updating Counter pricing immediately), or move items to the supplier return list.
3. Sell the discounted dead-stock item at the Counter (via search + `Enter`, category browse, or the Counter Dead-Stock Bundle suggestion) and watch trapped capital, dead-stock tabs, and alerts update immediately on bill completion.
4. Switch to **Restock** (`/restock`) to review forward demand forecasts (*Demo forecast*) and add out-of-stock fast movers to a Purchase Order.

## Stage 2 Inference Backend

The Flask backend receives the current frontend ledger (`products`, `sales`, and `suppliers`) as JSON from the Restock panel. It does not load a second product catalog or use the retained FMCG CSV. Fresh demo ledgers contain 120 days of deterministic, varied synthetic sales for all 47 seeded products; these transactions have `isSynthetic: true`. A fixed-date JSON export can be regenerated from the same frontend ledger code for repeatable backend validation. These are synthetic transactions, not actual store sales.

From the repository root, set up and run the backend:

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
pip install -r backend/requirements.txt
python backend/app.py
```

By default, Flask uses port 5000 and Vite uses port 3000. Set `VITE_API_BASE_URL=http://127.0.0.1:5000` in the frontend environment and run `npm run dev` in another terminal. If Vite cannot use port 3000, it can fall back to port 3001; the default backend CORS list permits both ports on localhost and 127.0.0.1.

If port 5000 is already occupied, run the backend on an alternate port and point Vite at it. For example, in Windows PowerShell:

```powershell
$env:PORT = '5055'
python backend/app.py
```

In a second terminal:

```powershell
$env:VITE_API_BASE_URL = 'http://127.0.0.1:5055'
npm run dev -- --port 3001
```

macOS/Linux equivalent: run `PORT=5055 python backend/app.py`, then `VITE_API_BASE_URL=http://127.0.0.1:5055 npm run dev -- --port 3001`. If using a frontend origin other than localhost/127.0.0.1 on ports 3000 or 3001, set `CORS_ORIGINS` on Flask to include that exact origin.

The existing `/api/restock/recommendations?limit=100&offset=0` route accepts `POST` JSON containing the ledger's `products`, `sales`, and `suppliers`, and returns a JSON array with `X-Total-Count`. Its original response fields remain available, with `product_id` and ledger-derived demand and stock. The API caches calculations for repeated identical payloads. `/api/health` reports service health. `/api/validation/report` also accepts a ledger payload by `POST`.

Reorder quantity is calculated for every product as `max(0, avg_daily_sales × (lead_time + 3) − stockQty)`, where average daily sales comes from its ledger sale lines over the ledger history window. Existing product and supplier types have no lead-time or MOQ fields, so the backend uses a documented 3-day lead-time fallback and does not round to MOQ. Optional `leadTimeDays` values on a product or supplier payload are honored. Seed sales are retrospective synthetic history and do not decrement the seeded current `stockQty`; live completed sales update both the sale ledger and stock.

The validation report evaluates SES (alpha 0.3) on a frozen-origin 14-day holdout from the same ledger sales data. Its metrics measure fit to synthetic demo history and do not establish real-world forecasting accuracy. Regenerate the deterministic ledger export and report with:

```bash
node scripts/export-demo-ledger.mjs
python -m unittest backend.test_inference_service -v
python backend/generate_validation_report.py
```

`backend/data/demo_ledger_export.json` is generated by calling the frontend's `createInitialLedger` seed path; it is not an independently maintained catalog. `backend/validation_report.json` records product and sale counts, holdout metrics per product and in aggregate, and recommendations calculated from that export. Existing browser `localStorage` ledgers are preserved; use the app's Reset Demo Data action to replace an older seed with the expanded synthetic history.

## Service Layer Interfaces (For Backend Integration)

UI components read from a single Zustand ledger store backed by typed async service contracts in `src/services/interfaces.ts`. This demo ships only local mock implementations; a future backend can replace them behind the same interfaces:

- `IProductService`: `getAll()`, `create(input)`, `update(id, patch)`, `setCounterDiscount(id, pricePaise)`, `setStopReordering(id, stop)`
- `IBillingService`: `getSales()`, `completeSale(input)`
- `IInventoryService`: `adjustStock(id, deltaQty)`, `returnToSupplier({ productId, qty, reason })`
- `ISupplierService`: `getAll()`, `getReturnList()`, `markReturnSlipGenerated(returnIds)`, `clearReturnedItem(returnId)`
- `ICustomerService`: `getAll()`, `create(input)`, `recordPartialPayment(customerId, amountPaise)`
- `IForecastService`: `getForecast(horizon)`, `getPurchaseOrders()`, `buildPurchaseOrder(items, supplier, sequence)`
- `IReportsService`: `getSalesSummary()`, `resetDemoData()`

## What Is Mocked in This Demo

- **Persistence**: All products, sales, customers, suppliers, supplier returns, and purchase orders are stored in `localStorage` (`src/services/mockServices.ts`) and seeded with relative dates around today (`DEADSTOCK_DAYS = 30`, `NEAR_EXPIRY_DAYS = 14` in `src/config.ts`).
- **Demand Forecasts (Restock)**: The local Restock recommendation panel calls the Flask inference endpoint. The separate in-app local reorder cards and horizon multipliers remain seeded estimates.
- **WhatsApp & Print**: Low-stock WhatsApp sharing opens `https://wa.me/?text=...` in a new tab; receipts and supplier return slips use `window.print()` with an A5/A4 print stylesheet (`Powered by Trexo`).
